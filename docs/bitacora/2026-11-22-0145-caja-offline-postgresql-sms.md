# 2026-11-22 01:45 · Caja offline PostgreSQL y envío de SMS

- **Qué cambió** Caja prepara un catálogo autorizado por 12 horas para el teléfono vinculado. En modo offline guarda la venta y el folio en un diario cifrado. PostgreSQL valida el catálogo original y aplica la venta, el pago y el movimiento de inventario en la misma transacción. El segundo cobro desconectado de la última pieza se conserva con un movimiento de faltante. El adaptador LabsMobile se habilita mediante variables de entorno.
- **Samsung SM-A165M** Con modo avión, Wi-Fi desactivado y el túnel USB de la API retirado, la app guardó una venta SIMULADA de MXN 21.00 con MXN 4.00 de cambio. Reabrió con el mismo folio tras detener el proceso. La consola cambió el precio a MXN 24.00 mientras el teléfono estaba desconectado. Al reconectar, el historial mostró el folio `f6d33dec-e3ab-53e0-87e3-603122fa90a9` una vez por MXN 21.00. PostgreSQL confirmó un pago y un movimiento de −1 pieza ligados a ese folio.
- **Pruebas** `./scripts/verificar.sh` pasó 336 pruebas de servidor con PostgreSQL, 16 de la app Python y el escaneo de secretos. Android pasó 176 pruebas y compiló el APK de release. La prueba PostgreSQL usó dos identidades de dispositivo autenticadas, reintento concurrente, un cambio de precio y un intento de otra tienda. Los casos del adaptador LabsMobile cubren ambos prefijos y el error del proveedor dentro de HTTP 200.
- **Pendiente** Probar el SMS de operador con una SIM mexicana y cuenta QA de LabsMobile. La colocación en un entorno PostgreSQL de staging sigue después de la prueba de SMS. La prueba física de dos cajas independientes y la recepción offline quedan pendientes.
